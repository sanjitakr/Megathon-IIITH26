# Data schema, labels and held-out predictions

All tables are generated by `make data` (seed 42, reproducible) into `data/processed/`. No real or personal customer data is used. Reference parameters are versioned JSON in `data/reference/` (placeholders to be replaced by sourced values; see `docs/data_sources.md`).

## Tables

| Table (file) | Key fields | Available at prediction time? |
|---|---|---|
| properties (`properties.parquet`) | property_id, customer_id, postcode (synthetic), region, property_type, age_band, floor_area, tenure, `form_json` (what the customer types, incl. *not sure*), `state_json` (true simulator state), split | `form_json`: **yes**. `state_json`: **no** (label side). |
| energy_usage (`energy_usage.parquet`) | property_id, month, electricity_kwh, gas_kwh, missing_flag | Yes (history). Missing months are null, never zero. |
| retrofit catalogue (`data/reference/retrofit_catalogue.json`) | retrofit, tier, applicability (rules in `engine/feasibility.py`), cost low/mid/high, effect ranges, disruption, source | Yes |
| emission factors (`data/reference/emission_factors.json`) | fuel, kg CO₂e per kWh, source, version | Yes |
| retrofit history | completed retrofits entered by the customer (`past_retrofits`) and stored in customer memory (`data/memory/`) | Yes |
| sales history | synthetic sales generated by `ml/value_model.py --synthetic-demo` (price, date, floor area, type, region, age band, EPC band at sale) | **Training only**; never a feature for energy models |
| current value estimate | customer input `current_value_estimate` (baseline for the value range), kept separate from sale prices | Yes |
| labels (`labels.parquet`) | clean simulated kWh per fuel, rating, feasibility, per-retrofit and package per-fuel deltas, improvement potential, observed (noisy, annualised) usage | **No**: reference only |
| hidden_state (`hidden_state.parquet`) | behaviour, build quality, appliance and hot-water factors, setpoint | **No**: never an input |

Features are built only from `form_json` (`ml/features.py`), the same function at training and prediction time; `gen/splits.NOT_AVAILABLE_PREFIXES` lists label-side columns.

## How labels are generated (disclosed rules)

1. **Sampling** (`gen/sampling.py`): conditional chain region → type → age → floor area | type → fabric | age → heating | age, region (`data/reference/sampling_priors.json`). 30,000 homes; about 12% of customers own 2–3 homes.
2. **Simulation** (`sim/`): monthly heat-loss model (HLC = ΣUA + 0.33·n·V, heating degree-days base 15.5 °C), boiler and heat-pump efficiency with a heat-loss penalty on heat-pump SCOP, hot water, appliances, cooking, and a solar/battery energy balance. Hidden per-home factors enter the simulation but are never features.
3. **Calibration** (`gen/calibration.py`): global parameters fitted so simulated medians by type × age match NEED-style medians (placeholders) — plausibility evidence only (`docs/calibration_report.md`).
4. **Labels** (`gen/labels.py`): clean baseline per fuel; EPC-style rating (SAP-like formula, standard prices and occupancy); feasibility from documented rules; standalone and full-package per-fuel savings, each from re-running the simulator with the retrofits applied to its inputs, so interactions are real; improvement potential.
5. **Observation** (`gen/noise.py`): observed = clean × exp(ε), ε ~ N(0, 0.08²); 25% of homes lose 0–4 random months; 1% monthly sensor spikes; ~8% of optional answers become *not sure*; EPC band known for 60% (20% of those off by one band).

**Agreement with these synthetic targets does not establish real-world predictive accuracy.**

## Splits

`GroupShuffleSplit` by **customer**: train 17,097 / validation 3,658 / test 3,679 homes, so no property or customer is in two splits. A separate out-of-distribution test set (4,462 homes) holds out one region (Wales) and one age band (1900–1929) entirely; 1,104 other homes of those customers are excluded. Checked by `check_no_group_leak`.

## Held-out test predictions (`make predict` → `data/predictions/`)

`test_predictions.csv` — one row per test home (3,679 rows), engine run with the noisy, partly missing usage a customer would supply:

| Column | Meaning |
|---|---|
| property_id, region, property_type, age_band | identifiers / context |
| status, tier | `ok` or `insufficient_information`; confidence tier A/B/C |
| pred_baseline_electricity_kwh, pred_baseline_gas_kwh | engine baseline (purchased energy), kWh/yr |
| pred_score, pred_class, pred_is_poor, pred_key_issues, pred_band | Green Home Score outputs |
| pred_improvement_potential_pct | improvement potential, full feasible package |
| pred_feasible_retrofits | feasible retrofits in priority order |
| pred_pkg_d_elec_kwh, pred_pkg_d_gas_kwh, pred_pkg_carbon_saving_kg | full-package per-fuel savings (negative = increase) and carbon |
| pred_recommended, pred_recommended_d_elec_kwh, pred_recommended_d_gas_kwh, pred_recommended_carbon_kg | package for the default goal and its savings |
| ref_baseline_*_kwh, ref_pkg_d_*_kwh, ref_improvement_potential_pct, ref_band, ref_sap_points | simulator reference labels for comparison |

`portfolio_ranking.csv` — the same homes ranked by improvement potential, with Poor flags, key issues and the recommended package.

Money is computed in the engine's internal currency and displayed in ₹ at the placeholder rate in `data/reference/currency.json`; prediction files contain energy, carbon and scores only.
